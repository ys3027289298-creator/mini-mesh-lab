# split

连通分量切分。每个分量有独立的紧凑顶点数组，面索引只在该数组内重新编号，
因此每个分量的索引都从 0 开始；分量之间不共享顶点；切分前后顶点数和面数守恒。

```
make test       # 2 / 3 / 5 分量回归，含交错顶点序
make diagnose   # 复现索引偏移并逐条排除四种候选原因
```

## 背景

报告症状：切成两个分量后，第二个分量的顶点索引整体偏移，渲染跑到屏幕外。

`make diagnose` 用两个三角形做最小复现，打印偏移前后的索引：

```
before fix:
  comp0 nv=3 nf=1 src=[0 1 2] faces= (0,1,2)
  comp1 nv=3 nf=1 src=[3 4 5] faces= (3,4,5)   <- 只有 3 个局部顶点，合法范围 [0,2]
after fix:
  comp0 nv=3 nf=1 src=[0 1 2] faces= (0,1,2)
  comp1 nv=3 nf=1 src=[3 4 5] faces= (0,1,2)
```

四条候选路径的排除依据（判别输入：顶点序交错，分量 0 拥有源顶点 0/2/4，
分量 1 拥有 1/3/5，分量 1 的局部面为 (0,1,2)）：

| 假设 | 预测 | 实测 | 结论 |
|---|---|---|---|
| H1 切分时没重排 | (1,3,5)，源索引原样 | (3,4,5) | 排除：偏移量不等于源索引，重排确实发生了 |
| H2 偏移量按全局算 | (3,4,5)，局部 + 累计基址 | (3,4,5) | **确认**：每个索引都等于局部值 + 该分量的累计顶点基址 |
| H3 分量间共享顶点 | 分量 1 的 src 与分量 0 重叠，总顶点数 > 输入 | src=[1 3 5]，与 [0 2 4] 不相交，总数 6/6 | 排除 |
| H4 索引表只拷贝一半 | 面数少一半，或索引出现 -1 | 面数 2/2，无 -1，(0,1,2) 完整 | 排除 |

H2 的进一步证据：多加的偏移恰好是累计顶点数——两分量时 +3，三分量（3/4/3）时
依次 +0 / +3 / +7，不是"每个分量 +1"，也不是源索引本身。把每个分量的基址减掉后，
所有面与绕序和输入完全一致。

`make diagnose` 的 C 段还反向验证了检测器真有牙齿：把四种故障分别注入正确输出，
每个检测器都恰好在对应故障上报警；D 段在观测输出上跑同一组检测器，`in_range` 和
`faces_via_src` 均为 0。
