# streaming：分块流式加载的预取/降级时序仿真

针对"大模型分块流式加载，边跑边把远处的块降级，但常出现刚加载完就被降级"的
浪费问题，把**预取**与**降级**两条判定都写成时间的函数，用帧级仿真在三档移动
速度下量化：预取提前量、刚加载即降级的块数、视野内缺块帧数。

运行：

```bash
python3 -I src/sim.py --out ../artifacts/streaming/results.json
```

## 1. 符号

| 符号 | 含义 | 仿真取值 |
|---|---|---|
| `S` | 块边长（一个块沿运动方向的跨度，m） | 10 |
| `D` | 视野深度（m） | 40 |
| `v(t)` | 相机瞬时速度（m/s），`v̄` 为平均速度 | 三档 4 / 12 / 24 |
| `t_net` | 单块网络传输时间（带宽共享下为有效值，s） | 字节/带宽 |
| `t_dec` | 单块解码时间（s） | 0.20 ± 0.06 |
| `t_load = t_net + t_dec` | 一个块从发请求到就绪的完整加载预算 | — |
| `T_hold` | 降级安全时间（s） | 0.60 |
| `x(c)`、`x(t)` | 块 `c` 前边缘位置、相机位置 | — |

## 2. 两条判定都是"剩余时间"的函数

### 2.1 预取时机：提前量 = 速度 × 解码时间估计

块 `c` 进入视野的剩余时间（按当前速度外推）：

```
T_enter(c, t) = (x(c) − x(t)) / v(t)
```

预取触发条件——剩余时间不足以覆盖一个完整加载周期时发请求：

```
T_enter(c, t) ≤ v_est · t_load,   等价的距离提前量  d_pf = v_est · t_load
```

其中速度估计 `v_est` 是两种策略的唯一差别：

- **avg（按平均速度定提前量）**：`v_est = v̄ = x(t)/t`（全程均值，对速度阶跃反应迟钝）；
- **inst（按瞬时峰值定提前量）**：`v_est = 1.15 · max{v(τ) : t−0.3s ≤ τ ≤ t}`，
  再乘触发余量 1.10。

### 2.2 降级判定：看该块在视野内的预计停留时长

块 `c` 后边缘离开相机的剩余距离是 `(x(c)+S) − x(t)`，故预计剩余驻留时间：

```
T_dwell(c, t) = (x(c) + S − x(t)) / v(t)
```

降级触发条件——剩余驻留时间已不够一个安全窗口，保留它的收益低于释放它的成本：

```
T_dwell(c, t) < T_hold
```

"刚加载完即降级"的浪费判据：块就绪后实际服务时长不足 `T_hold` 就被降级，

```
t_degrade(c) − t_ready(c) < T_hold
```

## 3. 两个条件如何衔接：预取应早于降级多少

一个块从"被预取"到"被降级"的时间轴是

```
预取受理 ──t_load──> 就绪(active) ──(服务)──> 降级(degraded)
```

块在视野内的总停留时长约为 `L/v`，其中 `L = S`（相机越过整块的路程；若以
进入远裁剪面到离开计则为 `D+S`）。要避免"刚加载完即降级"，必须满足

```
(加载预算) + (最低服务时长) ≤ (视野内总停留时长)
t_load + T_hold ≤ L / v
```

因此**预取应早于降级的时间量**（两者触发时刻之差）为

```
Δ = t_load + T_hold − L / v
```

- `Δ ≤ 0`：块停留足够久，预取再晚也来得及，不会即降级；
- `Δ > 0`：即使在进入视野瞬间就预取，就绪后也驻留不满 `T_hold`，
  这块的解码成本注定被浪费——这正是高速档的结构性浪费。
  临界速度 `v* = L / (t_load + T_hold)`：仿真参数下 `v* ≈ 10 / (0.286+0.60) ≈ 11.3 m/s`，
  与"中速档开始出现个位数即降级、高速档升到 12~13 块"的实测一致。

预取侧的安全写法是把 `v_est` 取近期峰值而非均值，使触发距离
`d_pf = v_est·t_load` 在加速前就铺好；降级侧仍按瞬时 `T_dwell` 判定，
两者通过同一个 `t_load + T_hold` 预算衔接，而不是各用各的常数距离。

## 4. 仿真模型

- 20s 周期行程：巡航 8s → 2s 急加速到目标速度 → 高速巡航 8s → 2s 减速，
  叠加小幅振荡；120s 共 6 个周期，7200 帧。
- 加载管线：`fetching`（带宽在所有在途块间均分）→ `queued` → 单解码槽
  `loading` → `active` → `degraded`。解码槽按紧急度（`T_enter` 小者优先）调度。
- 缺块：相机已越过块前边缘，而该块既未 active 也未 degraded（loading/fetching
  算"正在赶来"，degraded 算已服务，均不计）。
- 三档瞬时峰值：8.2 / 20.5 / 39.0 m/s。

## 6. 结论

1. **高速档缺块帧数最多（374 帧），证实按平均速度定的提前量跟不上瞬时速度。**
   高速档瞬时峰值 39 m/s 是均值 24 m/s 的 1.6 倍，急加速的 2s 过渡期内，
   按 `v̄·t_load` 铺的预取距离被瞬时速度快速吞没，块进入视野时请求仍在途。
2. 把速度估计换成近期瞬时峰值后（inst），高速档缺块从 374 降到 245（−35%），
   过渡期提前量从 8.13s 增到 9.05s；代价是巡航段会略微过度预取（低速档提前量
   1.61s→2.44s），但不产生缺块或即降级。
3. **即降级是结构性浪费，不靠调预取策略消除。** 高速档 13 块即降级对应
   `Δ > 0` 区间（`v > v* ≈ 11.6 m/s`）：这些块的视野驻留时间本身就短于
   `t_load + T_hold`。正确应对是对高速掠过的块直接请求低 LOD（更短的
   `t_load` 使 `Δ` 回落到 0 以下），而不是用全分辨率块加载完立刻降级。
4. 稳态巡航段两种策略的提前量会收敛到同一工作点（差距只在加减速过渡期显现），
   所以评估预取策略必须看**过渡期提前量**与瞬时峰值的并列，而非全程均值。
