# layout: AoS vs SoA 顶点存储实测

顶点 32 B（pos 12B + nrm 12B + uv 8B）。AoS = 结构体数组；SoA = pos/nrm/uv 三条平行数组。
测试机：Ryzen 7 9700X（L1d 48K / L2 1M / L3 32M，64 B 缓存行），gcc 13，`-O2 -ffast-math -march=native`，单核钉核，取多批最小值，单位 ns/顶点。

换算成顶点数，每级缓存能装：L1 = 1.5k(AoS) / 4k(SoA-pos)，L2 = 32k / 87k，L3 = 1M / 2.8M。

## 数据

100k 以内是题目范围；300k–3M 是为暴露渐近行为加的参考点。

## 结论

**1. 全字段顺序遍历：两种存法无差别，没有交叉点。** 每顶点都是 32 B，硬件预取器对 1 条流和 3 条流同样有效（full 行两列始终相等即为证据）。

**2. 部分字段顺序遍历：交叉点在"被访问的流溢出末级缓存"处，本机约 300k–1M 顶点（L3 32MB）之间。**
题目范围（≤100k = 3.2MB）内整个顶点集都住在 L3 里，且 bbox 每顶点 ~3 周期是计算受限，所以看不到差别。
溢出 L3 后 SoA 反超，比值趋向字节比 32:12（trav_x 实测 0.94/0.46 ≈ 2.0；bbox 被计算下限压在 1.5）。
**原因是缓存行利用率，不是预取**：两种布局的顺序流都被完美预取，但 AoS 每搬一条 64 B 行只用其中 12 B 的 pos，62% 的带宽被 normal/uv 浪费；SoA 的 pos 数组是稠密的，每个字节都用上。

**3. 随机单点访问：AoS 的缓存层级拐点比 SoA 早 32/12 ≈ 2.67 倍顶点数。**
AoS 在 ~1.5k 顶点溢出 L1、~32k 溢出 L2、~1M 溢出 L3；SoA 的 pos 数组分别在 ~4k、~87k、~2.8M 才溢出。
实测依赖链延迟完美踩在容量边界上：3k 顶点时 AoS 已掉进 L2（2.6ns）而 SoA 还在 L1（1.2ns）；100k 时 AoS 全在 L3（10.4ns）而 SoA pos 1.2MB 大半还在 L2（5.9ns）；1M 时 AoS 32MB 溢出 L3 掉进 DRAM（138ns）而 SoA pos 12MB 仍在 L3（14ns）。
**这是缓存行容量效应**：同样的字节预算，稠密数组能装的顶点数是结构体数组的 2.67 倍。

**4. 随机全字段访问方向相反：AoS 赢。** 一次随机访问 AoS 只 miss 1 条缓存行，SoA 要在 3 个数组各 miss 1 条。100k 起 SoA 开始落后（1.25 vs 0.97），DRAM 区扩大到 8.5–10.0 vs 7.8–8.1。

**5. 预取的作用：它决定绝对量级，但不决定谁赢。** 同一批缓存行，顺序遍历 0.4 ns/顶点 vs 随机依赖链 1.2–160 ns/步，两个数量级的差全部来自预取器；但预取器对两种布局是中立的——顺序时两者都受益，随机时两者都失效。所以交叉点要用缓存行解释，不能用预取解释。

## 实践建议

- 顶点集能常驻缓存（本机 ≲ 100k 顶点）：随便选，没区别。
- 大网格 + 只摸部分字段的遍历（bbox、剔除、位置pass）：SoA，省的是缓存行带宽。
- 大网格 + 按索引随机取整个顶点（蒙皮 gather、邻域查询）：AoS，省的是 miss 条数。
- 两者都要：按访问频率拆——热字段（pos）单独一条流，冷字段交错，即 GPU 顶点流的混合布局。
