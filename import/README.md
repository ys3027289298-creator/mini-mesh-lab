# import

OBJ 模型导入管线，分四段计时：读取 → 解析 → 焊接 → 建索引。

- `make test` 跑自检（朴素焊接 vs 哈希网格焊接结果一致性、索引校验）。
- `make bench` 生成 250×250 网格基准数据（14MB，顶点按面角点重复），依次跑三种模式。

## 模式

| 命令 | 说明 |
|---|---|
| `./import --legacy f.obj` | 旧加载器：焊接内联在解析循环里，只有一个"解析"计时 |
| `./import f.obj` | 分段计时，朴素 O(n²) 焊接 |
| `./import --fast f.obj` | 分段计时，哈希网格焊接（优化后） |

## 结论（250×250 网格，37.5 万顶点 / 12.5 万面）

| 阶段 | 优化前 (ms) | 优化后 (ms) |
|---|---|---|
| 读取 | 23 | 14 |
| 解析 | 39 | 39 |
| 焊接 | 10391 | 15 |
| 建索引 | 1 | 1 |
| **合计** | **10455** | **69** |

瓶颈是焊接的 O(n²) 最近点查找，不是解析。旧代码把焊接内联在解析
循环里，单计时器把 99% 的耗时记在了"解析"头上，导致误判。优化只
动焊接：按 eps 划空间哈希格，每顶点只查 27 个邻格，O(n) 期望复杂度，
焊接结果（63001 顶点）与朴素版逐一致。
