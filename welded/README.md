# welded

顶点焊接、面片重映射、退化面剔除。`make test` 跑自检。

## 算法

旧实现是两重循环的 first-fit：每个顶点只和已经确定的代表点逐一比较，
复杂度 O(n²)，且在链式点列（A~B、B~C 但 A≄C）上结果依赖输入顺序。

新实现分三步：

1. **空间哈希分桶**：边长 `eps` 的规则网格，每个顶点按
   `floor(p/eps)` 落入一个桶（哈希表 + 链地址）。距离 ≤ eps 的两个点
   每个轴的网格坐标至多相差 1，所以只需要检查当前桶及 26 个邻桶（共 27 个），
   不可能漏掉任何近邻对。均匀分布下总比较次数 O(n)。
2. **并查集求等价类**：每发现一对距离 ≤ eps 的顶点就 union。最终等价类
   就是"距离 ≤ eps"关系图的**连通分量**——传递闭包，天然是等价关系。
3. **规范化编号**：每个分量取字典序最小（按 x,y,z 的 float 位序）的成员
   位置作代表，再按代表位置字典序给分量编号，焊接后的顶点数组与编号
   都不依赖输入顺序。

## 为什么分桶不破坏顺序无关性

顺序无关性由"被比较的点对集合"和"合并规则"共同保证，分桶只影响查找效率：

- 桶的划分只由顶点**坐标**和 eps 决定（`floor` 是纯函数），与顶点到达
  顺序无关；27 邻桶规则保证所有距离 ≤ eps 的点对都会被枚举到——
  `matches_bruteforce_pairs` 用 O(n²) 全配对暴力参照逐一核对了等价关系。
- 并查集的 union 满足交换律和结合律：以任何顺序 union 同一组边，得到的
  连通分量完全相同。分桶改变的只是边被发现的先后，不是边集本身。
- 分量编号和代表点位置都由坐标的字典序确定，不引用任何输入下标，因此
  连输出编号和焊接后顶点位置也与顺序无关（`shuffle_position_invariant`）。

注意：旧的 first-fit 贪心在链式数据上本来就不是顺序无关的（正序得到
{A,B},{C}，逆序得到 {B,C},{A}），本实现改为连通分量语义后才真正满足
该不变量；对原有用例（孤立重复点）两种语义结果一致，旧测试全部保留通过。

## 自检内容

- 原有行为测试（焊接计数、map、退化面剔除、非法 eps、空网格）
- `chain_*`：链式点列正序/逆序必须得到同一分组
- `shuffle_*`：300 点随机数据（含精确重复点与面片），5 种输入排列，
  比较每个原始顶点的类标签、重映射后的面片、焊接后顶点位置
- `matches_bruteforce_pairs`：与 O(n²) 暴力参照逐对核对
- `weld_10k_ms` / `weld_20k_ms`：规模翻倍耗时应近似翻倍（线性而非平方）

最坏情况（全部顶点挤进同一个桶，如大量完全重合点）退化回 O(n²)，
这是数据本身决定的桶内配对数，分桶结构不会增加额外开销。
