# 「导出后偶发少一块面」分支排查报告

结论先行。四条嫌疑逐条用最小输入打过真实的 `mesh_weld` / `mesh_add_tri`，并用 20 万组 fuzz 复核：

- **绕向冲突**：仓库里不存在任何绕向 / 正面 / 背面剔除分支，反向绕向的面原样保留，**排除**。
- **退化面（几何意义上、三个索引互异）**：代码没有叉积 / 面积剔除，共线零面积但索引互异的面**不会被丢**，**排除**。真正存在的退化剔除只有「焊接后两个索引撞成同一个」这一种索引判定（`src/welded.c:83`，基线 `:54`）。
- **重复索引**：字面重复索引在 `mesh_add_tri` 就被确定性拒绝（`src/welded.c:33`），三条两两相等判断齐全正确；它不是「有时候」的来源。
- **越界索引**：插入器判断正确（`src/welded.c:32`），但导出重映射路径（基线 `src/welded.c:53`）原来不再校验，直接 `m->map[f.a]`，绕过插入器喂入越界索引即栈越界读（UBSan/ASan 实证），Release 下读到相邻栈垃圾，可静默丢面 / 导出 `-1` 坏索引 / 崩溃。**这是第二个真实缺陷，已修**（`src/welded.c:77-81` 加范围校验 + `dropped_invalid` 计数）。
- **真正造成「合法面有时候被丢」的根因（首要修复）**：基线贪心「并入扫描到的第一个 ε 内代表点」（基线 `:46`）**不是等价关系、对顶点扫描顺序敏感**——两个彼此距离 `> ε` 的角点会因为都靠近某个更早的第三点而被并成同一个号，随后在 `:54` 被当退化面删掉。最小输入下同一几何仅换顶点顺序就是 `nf=0 / nf=1`，全部 24 种排列 **HEAD 有 8 种丢、16 种留**。已把焊接类接纳规则改成 **complete-linkage（全连接）**（`src/welded.c:48-67`）：新点必须与该类中**每个已有成员**都在 ε 内才能入类，从而保证 `map[u]==map[v] ⇒ |u−v|≤ε`。修后该最小面 **24/24 全部保留**；20 万组 fuzz 中「三条边都 `>ε` 却被丢」**0 例**、健全性违例 0、结构错误 0。

复现：

```sh
cd welded
make test       # 原有 10 项 + br_* 分支/回归项，末尾 all_ok=1，退出码 0
make sanitize   # 同一套自检过 ASan+UBSan，含越界索引用例
```

下列 `br_*` 检查都在 `branch_regression_checks()`（`src/welded.c:113`）里，由 `make test` 实际执行。

## 1. 所有能让面不进导出结果的分支

最终导出的面就是焊接压缩后的 `Mesh.f[0..nf)`。逐条路径（行号对应当前文件）：

| 位置 | 条件 | 对面的影响 | 属于题面哪一类 |
|---|---|---|---|
| `mesh_add_tri` `src/welded.c:31` | `nf >= MAXF(64)` | 返回 -1，不存储 | 容量（附带排查，边界正确） |
| `mesh_add_tri` `src/welded.c:32` | 任一下标 `<0` 或 `>= nv` | 返回 -1，不存储 | 越界索引 |
| `mesh_add_tri` `src/welded.c:33` | `a==b \|\| b==c \|\| a==c` | 返回 -1，不存储 | 重复索引 |
| `mesh_weld` `src/welded.c:49` | `eps <= 0` | 整体返回 -1，网格不变 | 非丢面分支 |
| `mesh_weld` `src/welded.c:77-81` | 面下标越界（**本次新增校验**） | `dropped_invalid++` 后跳过 | 越界索引（导出重映射） |
| `mesh_weld` `src/welded.c:83` | 重映射后 `a==b \|\| b==c \|\| a==c` | `dropped_degenerate++` 后 `continue`，**唯一删除已存储面的语句** | 退化面 / 焊后重复索引 |

全仓搜索 `cull|front|back|wind|orient|cross|fopen|fwrite|export` 没有任何绕向 / 背面剔除或真正的导出器；`normal` 只累加法线（`normal/src/normal.c:45` 仅统计零法线），`bbox` 只算包围盒，都不改 `nf`。

容量边界实测无 off-by-one：连加同一合法三角形，恰好接受 `MAXF=64` 个，之后返回 -1（`br_face_capacity=1`）。

## 2. 四类嫌疑的最小输入与判定依据

### 2.1 重复索引 —— 会被丢，但属于正确拒绝 / 正确剔除

最小输入 A：3 个顶点，插入 `(0,0,1)`。

```
add_tri(0,0,1) -> rc=-1, nf 0->0          # br_dup_index_rejected=1
```

依据：`src/welded.c:33` 三条两两相等判断齐全，`(0,0,1)` 命中 `a==b`。字面重复索引的三角形数学上退化，拒绝正确。

最小输入 B（索引互异、焊后才重复）：`v0=(0,0,0)`、`v3=(0,0,0)`，三角形 `(0,3,1)`。

```
add_tri(0,3,1) -> rc=0, nf=1              # 插入时索引互异，合法接收
mesh_weld(eps=1e-3) -> nu=3, nf=0, map[0]=map[3]=0
                                          # br_drop_accounting=1
```

两个角焊到同一点，导出三角形必然带重复索引，剔除正确；现在计入 `dropped_degenerate=1`，不再静默。

判定：**机制上确实「丢面」，但只丢真正退化（两角在容差内重合）的面，谓词正确。** 它「偶发误伤正常面」的唯一形式是第 4 节那个不健全的焊接分组，已修。

### 2.2 越界索引 —— 插入器安全；导出重映射路径有真实越界缺陷，已修

插入器这层（`nv=3`，合法下标 0..2）：

```
add_tri(0,1,99) -> -1
add_tri(0,1, 3) -> -1      # 恰好 == nv，边界也正确拒绝
add_tri(0,-1,2) -> -1
add_tri(0,1, 2) ->  0      # nv-1 合法，对照组        # br_oob_add_rejected=1
```

依据：`src/welded.c:32` 是 `a >= m->nv`（不是 `>`），`index==nv` 被拒、`nv-1` 放行。**只要面都经过 `mesh_add_tri`，越界索引进不来。**

但导出 / 焊接重映射原来不复查。构造导入网格的真实形态：3 个合法顶点，直接把面写成 `(0,1,99), nf=1`（不经 `mesh_add_tri`），在基线上跑 `mesh_weld`：

```
HEAD welded.c:53: runtime error: index 99 out of bounds for type 'int[64]'
ERROR: AddressSanitizer: stack-buffer-overflow ... READ of size 4
    #0 mesh_weld welded.c:53:63
```

普通构建里它能「跑过」（读结构体外栈内存），结果随栈布局而变：垃圾值恰好等于另一角 → 被 `:54` 静默丢面；垃圾值 -1 → 保留 `(0,1,-1)` 坏索引面（实测 `nf=1, c=-1`）；或崩溃。**这正是「有时候、无法稳定复现」的另一可能来源。**

修复（`src/welded.c:77-81`）：访问 `m->map[...]` 前先按 `m->nv` 校验 `ia/ib/ic`，越界则 `dropped_invalid++` 并跳过。修后：

```
mesh_weld -> nu=3, nf=0, dropped_invalid=1   # br_weld_oob_safe=1
make sanitize                                # all_ok=1，无 runtime error / ASan 报告
```

可达性说明：仓库自检的面都经 `mesh_add_tri`，所以这条在 toy 公开 API 内不可触发；但题面是「导出美术资产」，导入 / 反序列化通常直接填索引数组，该路径在真实管线可达，故按导出缺陷修复。

### 2.3 退化面（索引互异的几何退化）—— 没有对应剔除分支，排除

最小输入：三个互异索引但共线零面积 `(0,0,0),(1,0,0),(2,0,0)`，三角形 `(0,1,2)`，小容差焊接。

```
cross((1,0,0),(2,0,0))^2 = 0     # 几何零面积
add_tri(0,1,2) -> 0              # 只查索引不查面积，接收
mesh_weld(1e-4) -> nu=3, nf=1，面仍是 (0,1,2)
                                 # br_geodegen_distinct_survives=1
```

判定：代码**没有**叉积 / 面积阈值剔除，「几何退化」分支不存在，不可能由它丢面。退化只在焊接使索引重合时处理（2.1-B）。依据是零面积叉积 + 面数不变的实测。

### 2.4 绕向冲突 —— 没有绕向分支，两种绕向都保留，排除

```
同一三顶点，面 (0,1,2) CCW 与 (0,2,1) CW
mesh_weld(1e-4) -> nf 2 -> 2
f[0]=(0,1,2)  f[1]=(0,2,1)       # br_winding_both_kept=1
```

判定：没有任何按绕向 / 法线符号保留或剔除面的代码，焊接不读叉积符号，绕向不改变本导出器面数。绕向只影响法线朝向 / 光照，或下游查看器开背面剔除后的「看不见」，不属这里的面片丢失。旁证：`normal/src/normal.c:65` 用 `fabsf(n[0].z)` 断言，确实测不出法线翻转，但那是光照问题。

## 4. 「有时候」的确定条件，以及首要修复

### 4.1 确定条件：顶点扫描顺序 + 共享代表点

最小几何（`eps=0.1`）：

```
A=(0,0,0)  B=(+0.09,0,0)  C=(-0.09,0,0)  R=(0,1,0)
面 = (B,C,R)
```

`|A-B|=|A-C|=0.09 ≤ eps`，但 `|B-C|=0.18 > eps`；该三角形三条边 `BC=0.18`、`BR=CR≈1.004` 都 `> eps`，最短边约 `1.8·eps`，面积 `0.09`，并非零面积。HEAD 的「第一个 ε 内代表点」规则下边扫边建代表，于是：

| 顶点顺序 | HEAD 分组 | 面 BCR |
|---|---|---|
| `A,B,C,R` | A 先成代表，B、C 都并不健全地并入 A | `nf=0`（B、C 撞号，`:54` 删除） |
| `B,C,A,R` | B、C 相距 .18>.1 各成代表，A 并给 B | `nf=1`（保留） |

独立的全 24 排列扫描与本仓 `make test` 一致：**HEAD 8 个排列丢、16 个留**。DCC / 导出器若因哈希遍历、多线程、选择集顺序改变顶点写出顺序，就会在这 8/24 类顺序里命中丢面——这就是「同模型有时候少一块、重导又好」的确定条件。30 万组 fuzz 中 421 例出现「最短边 `>eps` 仍被共享代表点合并」，最大 `minEdge/eps≈1.82`（理论 ≤2），不是孤例。

### 4.2 修复：complete-linkage，保证「同号即真近邻」

`mesh_weld` 的入类规则改为（`src/welded.c:55-67`）：点 `i` 要并入类 `j`，必须与类中所有更早成员 `k`（`map[k]==j`）的距离平方都 `≤ eps²`。由归纳可得：

```
map[u] == map[v]  ⇒  |pos(u) − pos(v)| ≤ eps   （浮点舍入量级内）
```

因此一旦 `:83` 因两角同号而丢面，这两个角本身确实在容差内重合，剔除在任何顶点顺序下都成立；反之，三条边都 `>eps` 的面在任何顺序下都不可能被丢。修后同一用例：

```
[order-fix] 24 permutations: 0 drop BCR, 24 keep BCR
br_face_kept_all_orders=1
br_order_abcr_now_kept=1      # HEAD 必丢的 ABCR 顺序现在保留
```

我另写了 20 万组随机 fuzz 校验这条保证：`soundness_violations=0`、`all-edges>eps_dropped=0`、`structural_bad=0`。原有 10 项自检数值不变（`weld_count=3`、`map_zero/map_one=1`、`degenerate_dropped=1` 等）。

### 4.3 一个诚实的边界

first-fit complete-linkage 仍按扫描顺序建类，在极端「临界直径点链」上，**类的数量 / 顶点编号**理论上仍可能随排列变化；本修复保证的是与丢面直接相关的性质（同号必近、合法面不被误删）在所有顺序下成立。若还要求「分组 / 顶点序列本身与顺序完全无关且两两不连锁」，需要确定性直径聚类或空间量化全序键，是更大的独立改造（本任务家族里也另有题目专门做确定性焊接），不夹在本次丢面修复中。

## 5. 为什么没有用并查集 / 传递闭包

最直接的「顺序无关等价类」做法是对所有 `dist≤eps` 的点对做 union-find，但它是单链接传递闭包，会沿点链把相距很远的端点合成一类，反而丢更大的面。实测反例：21 个点排成 `x=0,0.09,…,1.80` 的链（相邻 .09<eps=.1），大三角形取远端点 `(0,20,R)`，长边 `1.8 = 18·eps`：

```
HEAD 贪心 / 现 complete-linkage: nu=12, 大面 nf=1（保留；不沿非代表点连锁）
union-find 传递闭包实验版       : nu=2, map[0]=map[20]=0, 大面 nf=0
```

而且对第 4 节的复现面，union-find 会因 `P~A~Q` 让它在**所有 24 种顺序下都被丢**——只是把「有时候少面」变成「总是少面」，不符合「把少掉的面修好」。complete-linkage 既消除了误丢，又没有这种连锁，故选用它。
